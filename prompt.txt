# A. Business flow yang harus dipahami

PROJECT-01 menggunakan konsep:

```text
Batch
→ memiliki banyak buyer
→ setiap buyer memiliki MemberOrder
→ setiap MemberOrder memiliki item/payment/status/tracking masing-masing
```

Admin bekerja terutama berdasarkan Batch.

Flow utama:

```text
Admin membuat Batch
→ membuka Batch
→ menambahkan buyer ke Batch
→ menentukan item/variant/qty
→ MemberOrder dibuat
→ seluruh buyer mengikuti progress utama Batch
→ individual MemberOrder hanya menyimpan kondisi individual seperti pembayaran, shipment, exception, override, dll.
```

Karena itu:

- Batch adalah pusat operasional utama;
- MemberOrder tetap penting sebagai entity transaksi individual;
- tetapi MemberOrder/Pesanan tidak perlu menjadi primary navigation terpisah.

# B. Hapus upload QRIS dari form Tambah/Edit Batch

Saat ini form Tambah Batch memiliki upload QRIS.

Ini tidak efisien karena QRIS OceanPaws digunakan berulang pada banyak Batch.

QRIS bukan properti unik suatu Batch.

QRIS adalah global payment method milik bisnis.

Hapus requirement dan UI:

```text
Upload QRIS pembayaran
```

dari create/edit Batch.

Jangan meminta admin upload QRIS setiap membuat Batch.

Form Batch baru harus fokus hanya pada data yang benar-benar milik Batch.

Contoh struktur form:

```text
IDENTITAS BATCH
- nomor batch otomatis
- nama batch

KATALOG
- foto katalog
- batas pemesanan
- tampilkan di katalog

VARIASI BARANG
- tambah variant
- harga
- DP/full price jika digunakan

PEMBAYARAN
- skema pembayaran:
  - Full
  - DP

Jika DP:
- nominal/default DP bila memang digunakan

Metode pembayaran:
QRIS OceanPaws
status: Aktif

[Kelola metode pembayaran]

PROGRESS
- status awal
- tanggal mulai
- tanggal selesai

INFORMASI
- deskripsi
- catatan admin
```

Jangan tampilkan file input QRIS pada Batch.

# D. QRIS aktif

Sistem harus dapat menentukan QRIS/payment method yang sedang aktif.

Untuk sekarang business rule-nya:

- satu QRIS utama dapat digunakan berulang;
- admin dapat mengganti QRIS aktif;
- QRIS lama jangan dihapus secara destruktif jika pernah dipakai;
- QRIS lama dapat dibuat inactive;
- payment method baru dapat dijadikan active.

Jika perlu, enforce hanya satu payment method aktif per type `qris`.

Contoh:

```text
QRIS Lama
Inactive

QRIS OceanPaws Baru
Active
```

Jangan overwrite file QR lama jika hal tersebut membuat histori transaksi kehilangan referensi lama.

# F. Form Batch harus menggunakan Payment Method aktif

Ketika admin membuat Batch:

jangan menyimpan duplicate QR image baru ke Batch.

Jika ada satu payment method aktif, tampilkan informasi seperti:

```text
Metode pembayaran

QRIS OceanPaws
Aktif

Pembayaran untuk Batch ini akan menggunakan payment method aktif.
[Kelola]
```

Jika belum ada payment method aktif:

tampilkan warning yang jelas.

Contoh:

```text
Belum ada metode pembayaran aktif.
Atur QRIS terlebih dahulu di Pengaturan Batch.
```

Jangan silently gagal.

Tentukan secara aman apakah Batch perlu:

- reference ke `payment_method_id`, atau
- menggunakan payment method global saat invoice dibuat.

Pilih desain yang paling sesuai dengan struktur project existing.

Prinsip penting:

historical payment records tidak boleh berubah secara salah hanya karena admin mengganti QRIS aktif kemudian.

Jika Invoice domain sudah tersedia setelah audit, prefer Invoice menyimpan `payment_method_id`.

Jika Invoice domain belum tersedia dan implementasinya di luar scope task ini, siapkan struktur PaymentMethod dengan bersih tanpa melakukan refactor Invoice besar yang tidak diminta.

# I. MemberOrder tetap hidup sebagai detail transaksi buyer

MemberOrder tetap merupakan transaksi individual buyer dalam suatu Batch.

Struktur konseptual:

```text
Batch
└── MemberOrder
    ├── Member
    ├── Items
    ├── Payment
    ├── Invoice
    ├── Tracking
    ├── Shipment
    ├── Override
    └── Status
```

Jangan menghapus atau menggabungkan MemberOrder ke Batch.

Batch dan MemberOrder memiliki tanggung jawab berbeda.

Batch:
- progress utama Group Order;
- katalog/variant;
- periode;
- buyer list;
- overall operational context.

MemberOrder:
- buyer tertentu;
- item buyer;
- payment buyer;
- invoice buyer;
- tracking code;
- shipment buyer;
- exception/override individual.
